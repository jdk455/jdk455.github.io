能力详情 · 关于我 · 视角 03

从算法视角：GNN 与强化学习

在我接触过的工程问题中，图神经网络（GNN）与强化学习（RL）是两种最具"系统观"的算法范式 —— GNN 关心"结构如何编码"，RL 关心"决策如何优化"。前者把5G 核心网配置命令、卫星拓扑、区块链节点关系这类非欧几里得对象嵌入向量空间；后者把"做什么动作能让长期收益最大"形式化为可优化的目标。本页系统梳理这两条线 —— 第一章对比 GNN 与 RL 的本质差异；第二章从贝尔曼方程出发把 RL 的两条公理性分类轴「价值/策略」「在线/离线」与多智能体 MARL 讲清楚；第三章把 RL 工具链延伸到 LLM 时代（RLHF / DPO / GRPO）以及更前沿的 Agentic-RL，这一章我没有项目实战、但正在持续跟进，是我下一步的研究方向；第四章回到我已实战过的「GNN + RL 协同」研究主线（卫星路由专利）。

第一章 · 图神经网络 vs 强化学习

两种范式的本质差异
研究对象：GNN 解决"表示"问题 —— 如何把图结构（节点 + 边 + 全局）压缩为可被下游任务消费的向量；RL 解决"决策"问题 —— 在与环境交互中如何选择动作以最大化累积奖励。
监督信号：GNN 通常是监督 / 半监督 / 自监督学习 —— 训练样本是「图 → 标签」对；RL 是没有静态标签的，监督信号来自环境给出的奖励，且奖励经常是稀疏、延迟、嘈杂的。
数据分布：GNN 的训练样本通常 i.i.d.；RL 的样本是序贯相关的（s_t → a_t → r_t → s_{t+1}），状态分布本身又依赖于策略 —— 这是 RL 比监督学习困难得多的根因。
互补关系：GNN 是"地图（map）"，RL 是"导航员（navigator）"。在我做的 卫星 QoS 分簇路由专利 工作中，GNN-GRU 负责把全网链路质量矩阵 + 时序变化压缩成隐状态，QMIX 多智能体强化学习负责在此隐状态上做分簇路由决策 —— 两者天然耦合。
图神经网络（GNN）的核心机制：消息传递
统一框架（Message Passing Neural Network, MPNN）：
每个节点 v 在第 k 层的嵌入更新规则：
 m_v^(k) = AGG^(k)( { h_u^(k-1) : u ∈ N(v) } )  （聚合邻居）
 h_v^(k) = UPDATE^(k)( h_v^(k-1), m_v^(k) )  （更新自身）
不同 GNN 变种就是 AGG / UPDATE 两个函数的不同实现。
GCN（Graph Convolutional Network, Kipf & Welling 2017）：
聚合规则 H^(k) = σ( D̃^(-1/2) Ã D̃^(-1/2) H^(k-1) W^(k) )，其中 Ã = A + I。
本质是对称归一化的邻居均值 + 线性变换 + 非线性。优点是数学优雅、参数少；缺点是转导式（transductive） —— 训练好的模型不能直接泛化到没见过的节点。
GraphSAGE（Hamilton et al. 2017）：
采样 K 阶邻居 + 可学习的聚合函数（mean / max-pool / LSTM）。关键贡献是归纳式（inductive） —— 训练完后能直接对新节点做嵌入推断。
个人实践：在 5G 核心网意图驱动配置项目 中我用两层 GraphSAGE 对 5,333 个配置命令构成的知识图谱做节点嵌入，相比 GCN 在「新命令上线」的增量场景下显著更友好 —— 这正是 inductive 的实际价值。
GAT（Graph Attention Network, Veličković et al. 2018）：
把 Transformer 的注意力机制移植到图上 —— 用 attention 权重 α_{vu} 代替均值，让不同邻居对中心节点的贡献是可学习的：
 α_{vu} = softmax_u( LeakyReLU( a^T [W h_v ‖ W h_u] ) )
 h_v' = σ( Σ_u α_{vu} W h_u )
优点是对噪声邻居天然抗拒；缺点是计算开销大。
更深的 GNN（GIN / GraphSAINT / GraphMAE / GNN-GRU）：
• GIN（Xu et al. 2019）：用 MLP + sum 聚合，在理论上等价于 Weisfeiler-Lehman 图同构检验上界，是表达能力最强的 MPNN 之一。
• GraphSAINT：子图采样，让超大图也能小批量训练。
• GraphMAE：图自监督预训练，类似 BERT 的 mask & reconstruct 思想。
• GNN-GRU / Spatio-Temporal GNN：在时序图（如卫星链路质量随时间变化）上联合捕捉空间与时间依赖。我在 卫星 QoS 分簇路由专利 中使用 GNN-GRU 对 LEO-MEO 双层星座的时变拓扑做联合编码。
GNN 的局限：
① 过度平滑（Over-smoothing）：层数过深时所有节点嵌入趋同。
② 过度挤压（Over-squashing）：远距离信息在多跳传递中被压缩失真。
③ 异质性陷阱：当邻居与中心节点标签相反时（异质图），简单消息传递反而引入噪声。

第二章 · 强化学习：从贝尔曼方程出发

2.1 MDP 形式化：把"决策"变成可优化对象
马尔可夫决策过程（MDP）五元组：
 M = ⟨S, A, P, R, γ⟩
• S：状态空间（在我做的卫星路由中是「全网链路质量矩阵 + 缓冲队列 + 业务类型」）。
• A：动作空间（路由场景下是「为每条流分配到哪些路径上、各路径的分流比例」）。
• P(s' | s, a)：状态转移概率，刻画环境动力学。
• R(s, a)：即时奖励函数（路由场景下是「-时延 + 吞吐 - 丢包」的加权和）。
• γ ∈ [0,1)：折扣因子，权衡短期与长期收益。
策略与价值：
• 策略 π(a | s)：状态 → 动作分布。
• 状态价值函数 V^π(s) = E_π [ Σ_{t=0}^∞ γ^t r_t | s_0 = s ]
• 动作价值函数 Q^π(s, a) = E_π [ Σ_{t=0}^∞ γ^t r_t | s_0 = s, a_0 = a ]
RL 的目标是找到最优策略 π* 使得 V^π*(s) 在所有状态上最大。
2.2 贝尔曼方程：RL 的基石
贝尔曼期望方程（Bellman Expectation Equation）：
 V^π(s) = Σ_a π(a|s) · [ R(s,a) + γ Σ_{s'} P(s'|s,a) V^π(s') ]
 Q^π(s, a) = R(s,a) + γ Σ_{s'} P(s'|s,a) · Σ_{a'} π(a'|s') Q^π(s', a')
含义：当前价值 = 当下奖励 + γ × 期望的下一步价值。这是把"长期决策"递归压缩为"一步决策"的根本工具。
贝尔曼最优方程（Bellman Optimality Equation）：
 V*(s) = max_a [ R(s,a) + γ Σ_{s'} P(s'|s,a) V*(s') ]
 Q*(s, a) = R(s,a) + γ Σ_{s'} P(s'|s,a) · max_{a'} Q*(s', a')
把"期望"换成"取最大"，描述的就是最优策略下的价值递归关系。这一方程是 Q-learning、DQN、值迭代算法的直接来源。
方程的两层意义：
① 数学上：在有限 MDP 中贝尔曼最优方程是压缩映射，存在唯一不动点 V*，迭代必收敛 —— 这是值迭代（Value Iteration）算法的理论根基。
② 工程上：当 S 或 A 很大（无法精确求解期望）时，用神经网络做函数逼近得到 Q_θ(s, a)，把贝尔曼方程的两边差异作为损失函数 —— 这就是 DQN 与所有后续深度 RL 算法的统一基底。
2.3 第一条分类轴：Value-based vs Policy-based
Value-based（基于价值）：
不直接学 π，而是学 Q_θ(s, a)，由 argmax_a Q_θ(s, a) 间接得到策略。
• Q-learning（Watkins 1989）：表格法，更新公式 Q(s,a) ← Q(s,a) + α [r + γ max_{a'} Q(s', a') - Q(s,a)]。
• DQN（Mnih et al. 2015, Atari Nature 论文）：用 CNN 逼近 Q，三大工程贡献 —— Experience Replay（打破样本相关性）、Target Network（稳定 bootstrap 目标）、奖励裁剪。
• Rainbow DQN：把 Double DQN、Dueling DQN、Prioritized Replay、Noisy Net、Distributional RL、Multi-step 六项改进打包。
优势：样本效率高、训练相对稳定。
局限：argmax 操作要求动作空间离散且不太大；连续动作 / 高维动作直接吃瘪。
Policy-based（基于策略）：
直接参数化策略 π_θ(a | s)，用策略梯度定理更新参数：
 ∇_θ J(θ) = E_π [ ∇_θ log π_θ(a|s) · Q^π(s, a) ]
• REINFORCE（Williams 1992）：最朴素的策略梯度，用蒙特卡洛回报 G_t 代替 Q^π(s, a)。方差极大。
• TRPO（Schulman 2015）：用 KL 散度约束保证策略不剧变（trust region）。
• PPO（Schulman 2017）：把 TRPO 的硬约束改为 clipped objective，工程实现极简、效果好，目前已是 RL 微调（包括 RLHF）的事实标准。
优势：天然支持连续动作 / 随机策略 / 多模态动作分布。
局限：方差大、样本效率低。
Actor-Critic（融合方案）：
Actor 负责输出策略 π_θ(a | s)，Critic 负责估计 V_φ(s) 或 Q_φ(s, a) 作为 baseline 降低方差：
 ∇_θ J(θ) = E_π [ ∇_θ log π_θ(a|s) · A(s, a) ]，其中 A(s, a) = Q(s, a) − V(s)
• A2C / A3C：异步多 worker 收集样本。
• DDPG（Lillicrap 2015）：把 DQN 的"argmax"换成确定性策略 μ_θ(s)，专为连续动作空间设计。配套 Target Network + Replay Buffer + OU 探索噪声。
• TD3（Fujimoto 2018）：DDPG 的稳定化版本（Twin Critic + Delayed Policy Update + Target Smoothing）。
• SAC（Haarnoja 2018）：在目标里加熵正则项，鼓励策略保持随机性，探索更充分。当下连续动作 RL 的事实标准。
个人实践：我在 太赫兹卫星 QMR + 改进 DDPG 路由 中正是用 Actor-Critic 架构 —— Actor 输出每条路径的分流比例（连续动作），Critic 评估"在当前链路质量下分流方案的长期 QoS 收益"，配合软更新 τ=1e-3、OU 噪声 (μ=0, θ=0.15, σ=0.2)，训练奖励从 −65,400 提升至 +342,265。这是贝尔曼方程在工业场景下的完整工程化展开。
选型心智：
• 动作离散且不大 → DQN / Rainbow
• 动作连续 → DDPG / TD3 / SAC
• 任务需要随机性 / 多模态 → SAC / PPO
• 高样本成本（真实机器人）→ off-policy 算法（SAC / TD3）
• 高度并行可仿真（游戏）→ on-policy 算法（PPO / IMPALA）
2.4 第二条分类轴：On-policy vs Off-policy
定义：
• On-policy：用于更新的样本必须来自当前正在被优化的策略。策略一旦更新，旧样本立即作废。
• Off-policy：用于更新的样本可以来自其它策略（如历史经验、人类示范、其它智能体）。引入行为策略（behavior policy） μ 与目标策略（target policy） π 的分离。
典型代表：
• On-policy：SARSA、REINFORCE、A2C、A3C、PPO、TRPO、IMPALA（V-trace 修正）。
• Off-policy：Q-learning、DQN、DDPG、TD3、SAC。
SARSA vs Q-learning ——「on / off」最经典的对照实验：
两者更新公式仅一字之差：
 SARSA（on-policy）：Q(s,a) ← Q(s,a) + α [r + γ Q(s', a') − Q(s,a)]，其中 a' 是当前策略实际采取的动作。
 Q-learning（off-policy）：Q(s,a) ← Q(s,a) + α [r + γ max_{a'} Q(s', a') − Q(s,a)]，目标用 max 而不依赖实际动作。
差异的工程后果：在著名的"悬崖行走（Cliff Walking）"问题中，SARSA 会学到"沿安全路径走"（因为它把"探索动作的代价"纳入了价值估计），Q-learning 会学到"沿悬崖最短路走"（因为它认为最优策略不会掉下去）。这告诉我们：off-policy 学到的是"最优策略下的价值"，on-policy 学到的是"当前策略下的价值"，两者目标不同。
Off-policy 的关键技术 —— 重要性采样（Importance Sampling）：
当用 μ 采样估计 π 的期望时：
 E_π[f(x)] = E_μ[ (π(x) / μ(x)) · f(x) ]
路径上的重要性比 (π/μ) 累乘会带来巨大方差，因此 PPO / IMPALA 等"近 on-policy"方法引入 clipping / V-trace 限制比值。
Replay Buffer 与样本复用：
Off-policy 算法天然支持 Experience Replay —— 把历史 (s, a, r, s') 存入缓冲区反复采样，样本效率提升一个数量级。这是 DDPG / TD3 / SAC 在机器人控制等"高样本成本"场景几乎独霸的根因。
权衡矩阵：
维度On-policyOff-policy
样本效率低（用一次扔）高（反复用）
训练稳定性高中（需 target net + replay 等技巧）
探索-利用由策略本身决定可独立设计探索策略
分布偏移风险无高（need IS 或 clipping）
连续动作PPO / SAC 可DDPG / TD3 / SAC 可
2.5 多智能体强化学习（MARL）
挑战：当多个智能体共同决策时，每个智能体的最优策略依赖于其他智能体的策略 —— 环境不再 Markov（违反 stationarity），单智能体 RL 直接套用会发散。
典型范式：
• CTDE（Centralized Training, Decentralized Execution）：训练时共享全局信息，执行时每个 agent 只用局部观测。代表：MADDPG、QMIX、MAPPO。
• QMIX（Rashid 2018）：每个 agent 学独立 Q_i(τ_i, a_i)，再用单调混合网络把它们组合成全局 Q_tot，满足 argmax Q_tot = (argmax Q_1, …, argmax Q_n) 的 IGM 条件 —— 既保留协同又支持分布式执行。
• MAPPO：PPO 的多智能体扩展，actor 局部、critic 全局。
个人实践：在 卫星 QoS 分簇路由专利 中我把"每个卫星簇头"建模为一个 agent，使用 GNN-GRU + QMIX 多智能体协同决策 —— GNN-GRU 编码全网时空状态作为 Critic 的全局信息，QMIX 实现分簇局部策略 + 全局 Q 协同。这套架构正是为了在 LEO-MEO 双层星座下实现差异化 QoS 保障。

第三章 · LLM 时代的 RL：从 RLHF 到 GRPO 到 Agentic-RL（前沿延伸 · 研究方向）

为什么这一章必须存在 —— RL 工具链在 LLM 时代的复兴
经典 RL 在 2017 年 AlphaGo 后曾陷入"除游戏与机器人外难找落地"的尴尬期。2022 年 ChatGPT 出世把 RL 重新推到工业界的中心 —— RLHF（PPO）是 InstructGPT / ChatGPT 训练的核心阶段。2024 年 DeepSeek-Math / DeepSeek-R1 提出 GRPO，又把 RL 推到推理时代的中央 —— LLM 的"长思维链"能力是 RL 涌现的，不是监督训练教会的。2024–2025 年学界与工业界共同推进 Agentic-RL，把 RL 从"单步 token 输出"升维到"多轮工具调用的长轨迹"。

这一章我没有亲手训练过 LLM RL，但已经把它列为下一阶段的研究方向。原因有三：① 我已在网络路由场景熟悉 RL 工具链（DDPG / QMIX / Actor-Critic），切换到 LLM RL 算法语言基本不变；② Agent 视角页讨论的 Plan-Execute-Replan、MCP 工具调用与 Agentic-RL 是同一个问题的算法面与工程面；③ 这是把"算法视角 + Agent 视角 + 系统视角"真正闭环的唯一通路。
3.1 RLHF：PPO 在 LLM 上的落地（InstructGPT 范式）
三阶段流程（Ouyang et al. InstructGPT 2022）：
① SFT（Supervised Fine-Tuning）：用人类示范数据集做监督微调，让基座模型先学会"按指令回答"的格式。
② Reward Model 训练：人类对同一 prompt 的多个回答做 chosen / rejected 偏好对比，训练一个标量奖励模型 r_ϕ(x, y)。常用 Bradley-Terry 模型作为偏好概率分布。
③ PPO RL：以 SFT 模型为初始策略 π_θ，以 r_ϕ 为奖励信号，用 PPO 优化策略。
PPO 在 LLM 上的关键改造：
• KL 散度约束（reference model）：目标函数加上 −β·KL(π_θ ‖ π_ref) 一项，防止策略偏离初始 SFT 模型过远（避免"reward hacking" —— 模型为了刷分胡言乱语）。
• Token-level 优势估计：把整个 completion 拆成 token 序列，每个 token 是一个动作，用 GAE（Generalized Advantage Estimation）估优势。
• Value Head：在 Transformer 顶部加一个标量输出头作为 Critic，估计 V(s) 给 PPO 做 baseline。
• Clipped Objective：经典 PPO 的 clip(r, 1−ε, 1+ε) 防止策略更新过激（ε 通常 0.2）。
为什么是 PPO 而不是其它 RL 算法？
• 动作空间是 vocab（10w+ 离散），DQN argmax 不适用；
• 训练稳定性要求高，TRPO 的 trust region 太重，PPO 是最佳折中；
• On-policy 易于与大批量分布式训练（rollout → 训练 → rollout）配合。
痛点：
① 显存爆炸：同时载入 4 个模型 —— Actor、Critic、Reward Model、Reference Model，每个都是百亿参数级；
② 训练不稳定：reward hacking、policy collapse 频繁；
③ Reward Model 偏差：人类偏好数据噪声大，RM 容易学到不该学的"啰嗦 = 更好"等捷径；
④ 工程链路长：四阶段调参，做一次实验耗时一周以上。
代表实现：TRL（HuggingFace）、OpenRLHF、DeepSpeed-Chat、veRL（字节跳动开源）。个人跟进：已通读 TRL 与 OpenRLHF 源码，理解 PPO trainer 的 generation buffer + advantage 计算 + clipped loss 三段式实现。
3.2 DPO：跳过 Reward Model 的"RL-free" 捷径
核心洞察（Rafailov et al. NeurIPS 2023 Best Paper）：RLHF 的最优策略对 reward function 有解析解 r(x, y) = β·log[π*(y|x) / π_ref(y|x)] + const。把这一关系代入 Bradley-Terry 偏好模型，整个 RLHF 流程可以直接改写为一个监督学习损失：
L_DPO(θ) = −E[log σ(β · log(π_θ(y_w|x)/π_ref(y_w|x)) − β · log(π_θ(y_l|x)/π_ref(y_l|x)))]
其中 y_w 是 chosen（偏好）、y_l 是 rejected（拒绝）。
优势：
• 无 Reward Model：训练管线从四模型简化为两模型（policy + reference），显存砍半，训练稳定性翻倍；
• 无 RL 优化器：不再有 PPO 的 sample → reward → advantage 循环，纯监督学习；
• 数学优雅：用一个 sigmoid + log-ratio 把 RL 压缩成一行损失。
劣势：
• 性能上限受参考模型 π_ref 制约；
• 对偏好数据分布敏感，超出 π_ref 覆盖范围的样本难以利用；
• 无法处理"非偏好"奖励（如代码运行结果、数学答案对错）—— 这类用 GRPO 更合适。
衍生家族：
• IPO (Identity Preference Optimization)：用 squared loss 替代 sigmoid，缓解 DPO 在偏好对完全可分时的过拟合；
• KTO (Kahneman-Tversky Optimization)：基于行为经济学的损失函数，可用单点（chosen 或 rejected 任一）而非成对偏好；
• ORPO：把 SFT 与偏好对齐合并为单阶段；
• SimPO：去掉 reference model 进一步简化。
这一脉的趋势是不断"去 RL 化" —— 把 RL 改造为可监督学习的等价形式。
选型心智：偏好对齐 + 数据干净 → DPO 系；推理任务 + 有可验证 reward → GRPO 系（见下）；既要灵活性又要复杂奖励 → 老老实实跑 PPO。
3.3 GRPO：DeepSeek 的群组相对策略优化（推理时代主力）
来源：由 DeepSeek-Math 论文（Shao et al. 2024）首次提出，DeepSeek-V2 / V3 沿用，DeepSeek-R1 使其举世闻名。GRPO 全称 Group Relative Policy Optimization。
核心思想 —— 用"组内相对优势"替代 Critic：
① 对同一个 prompt q，让当前策略 π_θ 采样 G 个不同的回答 {o_1, …, o_G}（一个"group"）；
② 对每个回答用 reward model（或可验证器）打分得到 {r_1, …, r_G}；
③ 优势直接用组内归一化定义：A_i = (r_i − mean(r_1..r_G)) / std(r_1..r_G)；
④ 套 PPO 的 clipped objective + KL 散度约束：L_GRPO = E[ min(ρ_i A_i, clip(ρ_i, 1−ε, 1+ε) A_i) − β·KL(π_θ ‖ π_ref) ]，其中 ρ_i = π_θ(o_i|q) / π_old(o_i|q)。
为什么 GRPO 是"杀手锏"：
• 无 Critic Value Network：直接砍掉一个百亿参数模型，显存省 25–40%，PPO 训练 LLM 最大痛点之一被解决；
• Group-relative baseline 天然降方差：同组样本共享 prompt，组内对比比 critic 估计的 baseline 更准；
• RLVR 场景下惊人有效：当 reward 来自可验证器（数学答案、代码执行、单元测试通过），GRPO + 验证器 reward 让 DeepSeek-R1-Zero 从纯基座模型"涌现"长 CoT 推理能力，无需任何 SFT。
GRPO vs PPO（数学等价性视角）：
PPO 用 critic 估计 V(s) 做 baseline 减方差，GRPO 用 group mean 做 baseline 减方差。两者在数学上都属于 policy gradient + baseline 减方差 这一族 —— GRPO 是"不要 critic、改用蒙特卡洛组内基线"的特例。可以理解为：GRPO = PPO − Critic + Group Baseline。
DeepSeek-R1 的范式启示：
R1-Zero 证明了一件惊人的事 —— 不需要任何思维链 SFT 数据，仅靠 GRPO + 数学/代码可验证奖励，基座模型自己就能"涌现"反思（"wait, let me reconsider…"）、自我验证、回溯等高阶推理行为。这是 RL 工具链 6 年来最大的范式跃迁，意味着推理能力可以"用 RL 训出来"而不必依赖大量人工标注。
同期 / 后续衍生：
• REINFORCE++ / RLOO：用类似的"无 critic + leave-one-out baseline"思想，与 GRPO 殊途同归；
• DAPO（字节，2025）：在 GRPO 基础上加入动态采样、token-level 损失、不对称 clip 等改进；
• VAPO / GSPO：进一步优化 sample 效率与稳定性。
RLVR 关键 unlock：之前阻碍 RL 在 LLM 大规模应用的最大瓶颈是 "reward 从哪来"。RM 训练成本高、偏差大。RLVR (Reinforcement Learning with Verifiable Rewards) 把 reward 退化为"程序自动判分"：数学题用 SymPy 验答案、代码用单元测试、定理证明用形式化验证器。这让 RL 突破 RM 的"天花板"，是 R1 / o1 / QwQ 现象的核心驱动力。
3.4 推理时代的 RL：PRM、Self-play 与 Test-Time Compute
过程奖励 PRM vs 结果奖励 ORM：
• ORM (Outcome Reward Model)：只对最终答案打分（稀疏，credit assignment 难）。
• PRM (Process Reward Model)：对推理每一步打分（密集，更精细，但需要 step-level 标注数据集，如 OpenAI 的 PRM800K）。
• 权衡：ORM 简单但样本效率低；PRM 信号丰富但数据贵。当前主流是"ORM 主导 + PRM 辅助"。
Test-Time Compute（推理时计算）：RL 训练完之后，推理时再做一次搜索 / 采样进一步提升能力 —— Best-of-N 采样、Beam Search、MCTS、Self-Consistency Voting。o1 / DeepSeek-R1 / Qwen-QwQ 的核心创新正是把"训练时 RL 涌现 + 推理时长 CoT"两段融合。
Self-play 与自我演化：
• Constitutional AI / RLAIF (Anthropic)：让 AI 给 AI 打分，绕过昂贵的人工标注；
• Self-Rewarding LM (Yuan et al. 2024)：模型同时充当 Generator 和 Judge，迭代提升；
• Self-Play Fine-Tuning (SPIN)：模型与"上一版本的自己"对抗式训练；
• R1 路线："R1 → 蒸馏小模型 → 数据增强 → 训下一代 R1" 自我演化闭环。
个人观察：2024–2025 年 LLM RL 的研究曲线异常陡峭，几乎每月都有新算法。但所有这些算法的底层原理都没跳出第二章讲的贝尔曼方程 + Policy Gradient + 减方差技巧。这恰恰说明经典 RL 基础的价值 —— 工具变化快，原理变化慢。
3.5 Agentic-RL：把 RL 升维到 Agent 长轨迹
定义：Agentic-RL 是把 RL 从"单轮 token 输出"升维到"多轮工具调用 + 多步规划的完整 Agent 轨迹"上做优化。Agent 与环境（浏览器、文件系统、API、用户）持续交互，每步选择工具 / 参数 / 是否继续，最终在任务完成时获得 reward。这把 LLM 真正变成"会做事的 agent"而不只是"会聊天的 LM"。
三个代表性方向：
• Web Agent：在浏览器环境里完成任务（搜索、订票、填表）。代表工作：WebGPT (OpenAI 2021)、WebShop / Mind2Web / WebArena / Browser-Use。
• Tool-using Agent：训练模型主动调用外部工具。代表：ToolFormer (Meta 2023)、Gorilla、ToolLLM、ToolACE。
• Code Agent：在代码仓库 / 终端环境里修 bug、写代码。代表：SWE-agent (Princeton)、SWE-RL (Meta)、Devin (Cognition)、Claude Code。
四大核心挑战：
① Reward Sparsity（奖励稀疏）：长轨迹只有终点有 reward 信号，credit assignment 极困难；
② Action Space 爆炸：每步可选工具数 × 参数空间，搜索空间巨大；
③ Off-policy 数据复用：trajectory 长到几十轮，replay buffer 成本爆炸；
④ Environment 不可微 + 不可重置：浏览器、真实 API 调用无法回退，rollout 成本远高于游戏环境。
前沿技术路线：
• Step-level RL：用 PRM 给每一步打分，把稀疏奖励拆解到每步；
• Reflexion 风格自我评判：每个轨迹结束后让模型 reflect "上一轮哪里做错了"，把 reflection 注入下一轮；
• RAGEN / SWE-RL：基于 GRPO 把同 prompt 多次 rollout 的 trajectory 做组内对比；
• Synthetic Trajectory Bootstrap：先用强模型 (GPT-4 / Claude) 生成示范轨迹做 SFT，再用 RL 微调；
• AgentEvolver / AutoML for Agent：把 prompt / tool description / planning 策略本身也作为可演化的对象。
与 Agent 视角 的对应：
• Planning 层（ReAct / Plan-Execute-Replan）的策略本身就是 RL 优化对象；
• Tool-use 层的工具选择是 RL 的动作空间；
• Memory 层的检索策略可以作为子动作；
• MCP 协议为 Agentic-RL 提供了标准化的 action / observation 接口（这是 RL 工程化的关键前置）。
换言之，Agentic-RL = Agent 视角的算法面 + 算法视角的工程面。
个人观点：当前 Agentic-RL 的最大障碍不是算法，而是"训练环境基础设施" —— 大规模、可并行、可重置的真实环境模拟（如百万浏览器实例、隔离沙箱、可回放数据库）是缺位的。这一层一旦补齐，Agentic-RL 会迎来类似 ImageNet 之于 CV 的爆发。这也是我特别关注 Anthropic 的 Hermes Agent Runtime / Claude Code Skills 这类基础设施工作的原因 —— 它们正是 Agentic-RL 时代的"训练数据生产线"。
3.6 个人定位：从网络 RL 到 LLM RL 的迁移路径
我目前实战的 RL 是网络路由场景（QMR + 改进 DDPG、GNN-GRU + QMIX），状态是连续的链路质量矩阵，动作是连续的分流比例。下一阶段我希望把这一套工具切换到 LLM RL / Agentic-RL 场景，理由有三：
① 算法语言一致性：贝尔曼方程、Actor-Critic、PPO / DDPG / GRPO 这些工具，从卫星路由到 LLM 训练，本质同构 —— 只是 state / action / reward 的具体实例不同；
② 场景互补性：网络 RL 的状态是连续向量（链路质量矩阵 64×64），LLM RL 的状态是离散 token 序列（10w vocab × 数千长度）；前者训练我对"连续动作 + 多智能体协同"的理解，后者将训练我对"离散大动作空间 + 长轨迹 credit assignment"的理解。两类场景互补，能让我对 RL 工具链有更完整的把握；
③ 三视角真正闭环：Agentic-RL 是 Agent 视角（Planning + Tool-use）+ 算法视角（RL 优化）+ 系统视角（训练基础设施 + Service Mesh + 数据流水线）的天然交汇 —— 把 Agentic-RL 做明白，就是把我自我定位的三个视角真正联起来。

这一章我没有项目实战可以"展示"，但已经把 TRL、OpenRLHF、veRL、verl-agent、AgentR1 等开源 RLHF / Agentic-RL 框架通读、跑过 demo。这是我硕士最后一年和工作头两年的核心研究方向。

第四章 · GNN + RL 的协同 —— 网络方向研究主线（已实战）

为什么 GNN 和 RL 必须配合
网络路由 / 资源调度 / 共识协议优化等问题的状态空间天然是图结构，且决策本身是序贯优化过程。如果只用 GNN，能得到"当前图的好嵌入"但没有决策能力；如果只用 RL，要么需要手工设计 state feature（脆弱、低效），要么直接用 MLP 处理图状态（破坏图归纳偏置、样本效率灾难）。GNN 提供 state encoder，RL 提供 policy/value head —— 这是它们的天然分工。
个人研究路径：从 QMR + DDPG 到 GNN-GRU + QMIX
阶段一（毕业设计 / 项目）：QMR + 改进 DDPG 两段式多径路由 —— DDPG 输出每条路径的连续分流比例，Actor-Critic 在链路权重矩阵 W = α·D̂ + β·(1−B̂) + γ·L̂ 上做单智能体优化。详见 太赫兹卫星网络仿真项目。
阶段二（专利申请）：把单智能体扩展为多智能体 —— 每个卫星簇头是一个 agent，用 GNN-GRU 编码时空状态、用 QMIX 实现协同决策，覆盖 LEO-MEO 双层星座差异化 QoS 保障。详见 卫星 QoS 分簇路由专利。
下一步思考：把"路由决策"这一具体问题进一步抽象 —— GNN-GRU 编码 + 多智能体 RL 决策 + LLM Agent 元控制（决定何时重训、何时回滚），形成"算法 + Agent"协同的下一代网络自治范式。这正是我把"算法视角"与"Agent 视角""系统视角"并列的根因 —— 三者在我的认知中本来就是一个连续体。
